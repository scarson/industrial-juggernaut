## What each agent is good for

**Use random when:** you want the skill floor reference. Always loses to anything else.

**Use greedy-archetypes when:** you want to test "play one specific role" strategies. Currently legacy M1 agents.

**Use heuristic when:** you want the strong baseline. Captures most of the available skill in (c).

**Use lookahead2 when:** you specifically want to study 2P (c) gameplay. Don't use it in 3+P matchups — it doesn't generalize.

**Use lookahead2-multi when:** you want the "current strongest agent" for any player count. Beats heuristic at every count tested.

**Use lookaheadN(3+) when:** you want to see if even deeper search helps. Costly.

**Use MCTS when:** you want a research-flavored agent that learns from rollouts. Currently structurally bottlenecked by the heuristic leaf eval. Higher iterations don't help much.

## How they interact with the alliance layer

| Agent | Alliance-aware? |
|---|---|
| random | Yes (legalActions includes ally/break — random picks them when legal) |
| greedy archetypes | No (M1-era, predates alliance layer) |
| heuristic | Yes (samplePolicy generates ally/break candidates; weights tunable) |
| lookahead2 / lookahead2-multi | Indirectly (uses heuristic as opponent model) |
| lookaheadN | Indirectly (uses heuristic as opponent model) |
| MCTS | Yes via samplePolicy (PW) and fixedCandidates |

## How they interact with Tactical Depth (asymmetric base types)

When `baseTypesEnabled=true`, all agents benefit from the heuristic's per-subtype composition (since heuristic is the leaf evaluator for most):

| Agent | Subtype-aware? |
|---|---|
| random | Yes (legalActions emits subtype-typed actions, random picks) |
| greedy archetypes | No (uses scoreMove, not subtype-stamped) |
| heuristic | **Yes** (samplePolicy iterates subtypes when flag on) |
| lookahead2 / lookahead2-multi | **Yes** (uses heuristic at opponent + leaf) |
| lookaheadN | **Yes** (same) |
| MCTS | **Yes** (samplePolicy seeds PW; fixedCandidates iterates subtypes via legalActions) |
