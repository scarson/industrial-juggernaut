(a) NEVER `git commit` in it while an implementer subagent is active there — `git commit` sweeps the whole index, not just your `git add` paths; use `git commit -- <paths>` (pathspec-limited) or wait. (b) Isolated-worktree reviewer agents can wander into the main worktree via `git worktree list` + `git checkout` and leave it detached — every isolated-agent prompt MUST say "do ALL work strictly inside your own worktree." If a worktree turns up detached at a SHA you didn't check out, a wandering agent did it: stop it, `git checkout <branch>`, verify tip + test count. (Memory: `controller-worktree-index-race`.)
- **dev is strict-up-to-date:** `gh pr merge` refuses if the branch is behind dev. Rebase onto `origin/dev` in the worktree, `git push --force-with-lease`, wait for the re-triggered `check`, then merge. Retargeting a PR's base does NOT re-fire CI (the `pull_request` trigger is branch-scoped) — a push does; rebase to trigger.
- **Bundle discipline is the client's load-bearing invariant:** the entry chunk must never contain `src/agent`. `check:bundle` proves it for the client build, but Vite compiles ES workers as a SEPARATE Rollup build the guard never sees — the worker-quarantine (`generate.worker.ts` is the only `recordGame` importer) rests on the deep-import convention + manual grep of the built worker chunk.
